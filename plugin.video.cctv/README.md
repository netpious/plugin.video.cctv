# 央视网 · Kodi 插件

**v1.3 · 纯 Kodi 原生界面**

作者：netpious、dsh

在线浏览央视网（cctv.com）中的电视节目和文章。把内容拆成 8 个入口，每个都是独立页面，内容形态各自不同：图文报道、视频、体育赛事、电视栏目、剧集分集、直播。

```
央视网
├─ 首页      电脑版 CCTV 节目官网(tv.cctv.com)首页，6 个板块
├─ 新闻      要闻 国内 国际 社会 法治 科技 文娱 教育 健康（图文报道，可读全文）
├─ 视频      央视网视频库最新发布（4 万+ 条，20/页）
├─ 体育      19 个赛事频道 + 15 个央视名栏 + 赛事（比赛视频）
├─ 4K专区    4K/超高清专区（16 部，最高 1080P）
├─ 栏目      348 个电视栏目，先按 CCTV 频道分组，再进栏目看单期
├─ 直播      CCTV 各频道
└─ 搜索      关键词搜索，剧集单独成入口，点进去看分集
```

所有视频/图文条目都支持**长按下载**（见下）。

## 安装

**方式一**：Kodi → 设置 → 插件 → 从 zip 文件安装 → 选 `plugin.video.cctv-1.3.zip`
**方式二**：把 `plugin.video.cctv` 整个目录拷进 `%APPDATA%\Kodi\addons\`

装好后：插件 → 视频插件 → **央视网**。

## 下载（长按）

在任意列表里**长按**一个条目（遥控器 OK 长按 / 鼠标右键 / 键盘 `C`）会弹出菜单：

* 视频条目 → **下载…**：先弹清晰度选择框
* 图文条目 → **下载文本…**：直接把报道正文存成 `.txt`

清晰度选择框长这样，每一档都配一个预览按钮：

```
▶ 预览  1080P · 1920x1080 · 4.1 Mbps · 45:24
⬇ 下载  1080P · 1920x1080 · 4.1 Mbps · 45:24 · 约 1.3 GB
▶ 预览  720P  · 1280x720  · 2.0 Mbps · 45:24
⬇ 下载  720P  · 1280x720  · 2.0 Mbps · 45:24 · 约 660 MB
📁 下载目录：D:\Downloads\CCTV
```

* **▶ 预览**：用 Kodi 播放器直接放这一档，放 N 秒（默认 20，设置里可改）自动停，
  回到这个框再挑，能把所有档位逐个看完再决定下哪一档。
* **⬇ 下载**：逐片拉 HLS 分片写进同一个文件（明文 TS/H.264，播放器直接能播），
  带进度条、随时可取消；取消会删掉 `.part` 临时文件，不留半截。
* **📁 下载目录**：点它当场选目录并写进设置，下次自动记住。
* 同名文件不覆盖，自动变成 `xxx (2).ts`。
* 加密流（DRM）不会出现在列表里 —— 那些流解出来就是花屏，与其给你一个假「1080P」，
  不如只列真正能播的档位（见下面「画质」一节）。

## 画质（v0.4.1 重做）

央视点播接口给两套 HLS，名字只差一段，画质天差地别：

| 线路 | 内容 | 能不能播 |
|---|---|---|
| `/asp/hls/{档位}/…` | 明文 TS + H.264 | ✅ 正常 |
| `/asp/enc/hls/{档位}/…` | 同一套转码梯的**加密版**（TS 结构完好、SPS 也能读，但画面数据是加密的） | ❌ 解码满屏 `concealing/corrupt`，就是花屏/乱码 |

v0.4.0 用的正是 `hls_enc_url`（加密那套），所以「1080P」在 Kodi 里全是乱码。
v0.4.1 只走明文梯，并且做了三件事：

1. **自己拼档位地址**：`hls_url` 的 master 受 `maxbr` 限制，`maxbr=2048` 时连 720p 都不报
   （新闻联播只报 480p）；去掉 `maxbr` 并按 450 / 850 / 1200 / 2000 / 4000 / 6000 / 8000
   逐个试，把 CDN 上真实存在的档位都找出来。
2. **用 SPS 验分辨率**：只读分片开头 96KB，解 H.264 SPS 拿到**真实**宽高，
   解不出来（=加密/坏流）就不列给用户。所以标「1080P」就是真 1080P。
3. **剔除假档位**：CDN 上不存在的档位常常拿 480p 顶上（同一字节数），
   按「分片字节数与低档完全相同」判掉，避免列表里出现「1080P」实际是 480p。

实测（2026-10-31，28 个样本，0 失败）：

| 内容 | 最高档 |
|---|---|
| 4K专区 16 部 | **1080P · 1920x1080 · 4.1 Mbps**（真超高清，抽 6 部逐帧验证过） |
| 新闻联播 | 720P · 1280x720 · 2.0 Mbps |
| 视频库里的小央视频短片 | 720P（竖屏 720x1280） |
| 今日说法 / 动画大放映等老栏目 | 360P · 640x360（CCTV 公开流就只有这么高） |

**没有 2160p**：CCTV-4K 频道的明文梯最高就是 1920x1080/4096k（画面上有「CCTV 4K 超高清」
台标，但编码是 1080p）；CCTV-4K / CCTV-8K 直播线路探测不到。
比 1080p 更高的那档只在加密梯里，而且同样是加密花屏 —— 没有密钥，也不去碰 DRM。

## 各栏目说明

| 入口 | 内容 | 数据来源 |
|---|---|---|
| 首页 | 今日热门 / 直播导视 / 片库 / 看点 / 收视TOP榜 / 经典影视剧场 | 解析 `tv.cctv.com` 首页 HTML |
| 新闻 | 9 个子栏目，每页 80 条，点开可读全文 | `news.cctv.com/…/cmsdatainterface/page/<col>_<p>.jsonp` |
| 视频 | 全站最新视频，直接播放 | `media.app.cctv.com/vapi/video/vplist.do` |
| 4K专区 | 16 部超高清片，自动选最高码率 | `tv.cctv.com/4K/index.shtml` |
| 栏目 | CCTV-1~17 分组 → 348 个栏目 → 单期节目 | `api.cntv.cn/lanmu/columnSearch` + 栏目页/搜索兜底 |
| 直播 | 20 个频道 | `ldncctvwbcd/cdrmld<ch>_1/index.m3u8` |
| 搜索 | 关键词搜索；剧集归并成一个入口 | `search.cctv.com/m/if3g_search.php` |

### 关于「剧集」

央视搜索结果里，同一部剧的每一集都带相同的 `ALBUMID`。浏览器里它是一个剧集入口，
点进去才看分集。插件照做：搜索结果里同一个 `ALBUMID` 只保留一条，标成「（剧集）」，
点进去用 `getVideoListByAlbumIdNew` 拉分集列表，再选集播放。

## 体育（v1.1 新增）

体育分三层，对应浏览器里的两个地方：

```
体育
├─ 频道（19 个）      sports.cctv.com 顶部导航，去掉「推荐」（那一条就是首页本身）
│   ├ 奥林匹克频道 NBA CBA 中超 英超 德甲 法甲 意甲
│   ├ 羽毛球 乒乓球 电竞 台球 网球 F1 排球
│   └ 中国足球 国际足球 冬奥会 亚运会
├─ 央视名栏（15 个）  首页中间那几个方框里的节目
│   ├ 体育新闻 体育世界 体坛快讯 体坛晨报 体坛零距离 运动一起赢
│   ├ 天下足球 足球之夜 冠军欧洲 篮球公园
│   └ 棋牌乐 逐冰追雪 奥秘无穷 健身动起来 艺术里的奥林匹克
└─ 赛事              央视体育赛程里的比赛视频（v1.2 新增，见下一节）
```

* **频道页**：视频条目直接播，图文条目打开正文（长文进阅读窗，只有一两句话、
  实际带播放器的页面会直接播视频）。列表可逐页翻看，长按同样能预览/下载。
* **名栏页**：复用「栏目」模块的解析，列出该栏目最近 20 期。

内容来源分两种，原因是这些频道的页面本身差别很大：

| 频道 | 来源 | 实测 |
|---|---|---|
| NBA / CBA / 中超 / 英超 / 德甲 / 意甲 / 网球 / 排球 / 中国足球 / 国际足球 | 体育 CMS 接口（拼音栏目名） | 每频道 26~500 条，一页 80~100 条 |
| 奥林匹克频道 / 法甲 / 羽毛球 / 乒乓球 / 电竞 / 台球 / F1 / 冬奥会 / 亚运会 | 搜索接口按关键词兜底 | 每页 20 条，可翻到 400 条 |

为什么后面这 9 个要走搜索：它们要么是纯 JS 页面（奥林匹克频道、电竞、亚运会一条
链接都没有），要么落地页只剩全站推荐位的那 6~7 条视频 —— 而且每个频道的推荐位
是同一批（古德温砍下32分、孙颖莎3-2申裕斌…），拿它当频道内容没有意义。

## 赛事（v1.2 新增，v1.3 补技术统计）

数据来自央视体育的赛程站 `cbs.sports.cctv.com`，播放/下载复用现成链路：

```
体育 → 赛事
├─ 近期集锦        最近 3 天所有比赛的集锦合成一个视频列表（一步到视频）
├─ 今日赛程        今天全部比赛（2026-10-31 实测 32 场）
├─ 按日期          21 天日期轴：10-16 ~ 11-08，标「今天」
└─ 按联赛          NBA / CBA / 英超 / 中超 / 意甲 / 德甲 / 法甲 / 西甲 / 解放者杯…
    └─ 比赛        技术统计（文本）+ 该场全部集锦/回顾
```

* **比赛条目**：`勇士 112-95 湖人 · 已结束 · NBA · 杯赛 · 10-31 10:00  🎬`，
  `🎬` 表示这场有集锦；未开始的显示 `19:35 北京控股 vs 新疆广汇能源 · CBA`。
  排序是「进行中 → 即将开始（近的在前）→ 已结束（新的在前）」。
* **比赛视频**：接口 `/game/game_detail?id=<场次>` 的 `videoList[].originalId`
  就是视频中心 guid，直接走 `mode=play&g=…`，长按照样能「预览 / 选清晰度下载」。
* **技术统计**：`statistics/{football|basketball}/game/team_stats`（在 H5 页
  `pc_game_data.js` 里挖出来的，注意它挂在 `cbs-u.sports.cctv.com/` 根路径，
  没有 `/pc/` 前缀）。列表第一条就是它，标签上直接写摘要，例如
  `技术统计｜射门 14-5 · 射正 7-3 · 射偏 3-1`；点开是完整文本：

  ```
  法甲 2026-2027 联赛
  开赛：2026-10-31 04:05
  场地：皮埃尔-莫鲁瓦球场
  状态：已结束
  比分：里尔 1 - 0 朗斯
  分节：上半场 0-0 / 下半场 1-0

  技术统计（里尔 / 朗斯）
  射门：14 / 5
  射正：7 / 3
  射偏：3 / 1
  角球：10 / 2
  犯规：7 / 14
  越位：1 / 0
  黄牌：0 / 1
  红牌：0 / 0
  控球率：63% / 37%
  ```

  篮球对应的是投篮命中/出手、三分命中/出手、罚球命中/出手、篮板、助攻、抢断、盖帽，
  外加 `quarter_score` 的四节比分。
* **没有关联集锦的场次**：不再摆一个空目录，直接把这份技术统计文本弹出来 ——
  之前「点进比赛只有一个比分文件夹、没有视频」就是这种情况。

接口侧的三个坑（都写在 `portal.py` 的注释里）：

| 坑 | 现象 | 处理 |
|---|---|---|
| 赛程接口的 `videoList` 永远是空的 | 只有 `hasVideo` 标志位 | 逐场拉 `game_detail`（一场 0.25s，8 线程并行后「近期集锦」约 1~2s，带进度框可取消） |
| 不带 `leagueId` 的赛程只给「精选」 | 10-31 只回 5 场，实际 32 场 | 按联赛并行拉全再按场次 id 去重合并 |
| 按队名搜索会搜到往年的同两队比赛 | 2026-10-31 的 里尔 vs 朗斯 返回 2020/2024 赛季 | 兜底搜索必须卡「发布时间在比赛前后 2 天内」，宁可没有也不能张冠李戴 |

**清晰度上限是 640x360**：我抽了 10 条比赛视频逐档验过，明文梯最高就是 640x360
（8 条 640x360 / 2 条只有 480x270），连 22 分钟的整场回顾也是 360P。加密梯
`/asp/enc/hls/` 里确实有 1080P，但解出来是纯灰 + 70 条 H.264 报错（乱码），
`/asp/h5e/` 全线 403。所以插件如实按片源上限播放，不标 1080P。

**只有近三周**：`/game/date_list` 是滚动窗口（今天往前约 7 天、往后 13 天），
没有历史赛季；「世界杯」「欧冠」这两个热门联赛当前窗口里一场比赛都没有。

## 设置

| 项 | 默认 | 说明 |
|---|---|---|
| 每个板块最多显示条数 | 80 | 首页单个板块最多列多少条 |
| 显示缩略图 | 开 | 首页图片少，开启后会并发去视频页补封面，约多花 2~4 秒 |
| 下载目录 | `special://profile/addon_data/plugin.video.cctv/downloads/` | 设置里是目录选择框；也可以点清晰度框里的「📁 下载目录」当场改 |
| 预览时长 | 20 秒 | 预览每一档清晰度时放多久 |

> 设置定义（`resources/settings.xml`）用的是 Kodi 的旧版格式，类型名只能是
> `text` / `number` / `bool` / `folder` —— 写成新版的 `string` / `integer` / `boolean`
> 会让 Kodi 直接拒绝整份定义（详见修复记录 v0.4.2）。

## 实现要点

```
default.py              路由：首页/新闻/视频/体育/赛事/栏目/剧集/直播/搜索/播放/下载
resources/lib/net.py    纯标准库 HTTP（老 TLS 兼容、UTF-8/GBK 自动判别）
resources/lib/portal.py 结构化数据源：新闻、体育、赛事、视频库、栏目大全、剧集、首页分组
resources/lib/cctv.py   首页解析、guid→HLS、搜索、直播 CDN 探测
resources/lib/download.py  清晰度枚举 + HLS 分片下载 + 文本落盘
resources/lib/kodi.py   目录项构造 + 长按菜单 + 正文阅读窗
```

几个关键点：

* **首页**：抓的是 `tv.cctv.com`（CCTV 节目官网，也就是浏览器里看到的那个首页），
  不是 `www.cctv.com` 门户。首页每个板块是一个 `column_wrapper`，板块名在 `textTab`
  或 `bangdan_top` 的 `h3` 里，按标题切段即可拿到「今日热门 / 直播导视 / 片库 / 看点 /
  收视TOP榜 / 经典影视剧场」六个板块。
* **文章阅读**：Kodi 没有网页视图，报道正文抓下来后用内置 `Dialog().textviewer()` 显示。
  正文有两种模板：新闻频道的正文其实塞在 `var contentdate = '<p>…</p>';` 这段脚本里
  （页面本身只有「正在加载」的空壳），体育频道则写在 `<!--repaste.body.begin/end-->`
  之间、播放器脚本又混在正文 `<p>` 里。所以先按模板取块，再删 `<script>`、跳过
  `playerParas` 之类的噪声段落 —— 旧版是靠「没删脚本、`<p>` 正则顺手捞到」才读出来的。
* **长按下载**：Kodi 的「长按」就是列表项的上下文菜单，插件用
  `ListItem.addContextMenuItems()` 挂一条 `RunPlugin(plugin://…mode=download)`，
  点中后走 `DialogProgress` 逐片下载。
* **为什么不用 xbmcvfs 下载**：`xbmcvfs.copy()` 只对本地/已挂载路径有效，
  Kodi 没有「把 http 地址存成文件」的接口，所以自己写了个下载器（`download.py`
  不 import `xbmc*`，因此可以脱离 Kodi 直接单测）。
* **「几 P」按短边算**：央视有竖屏视频，分辨率写 720x1280，按长边算会错标成 1080P。
* **直播**：优先 `ldncctvwbcd/cdrmld{ch}_1`（时移流，最高 1080P，实测全链路可播），
  再退回 `ldncctvwbnd/ld{ch}_2`；腾讯云线路不带 Referer 会 403，所以优先挑不需要请求头的线路。
* **画质**：只走明文 `/asp/hls/` 梯，并用分片开头的 H.264 SPS 逐档验出真实分辨率，
  加密的 `/asp/enc/` 一律不用（详见上面「画质」一节）。
  ffmpeg 默认取 master 里第一条（央视把 480p 放最前），所以插件从来不把 master 交给 Kodi。
* **TLS**：`media.app.cctv.com` 不支持安全重协商，Python 3.10+ 默认拒绝，
  `net.py` 里用 `OP_LEGACY_SERVER_CONNECT` 兼容。
* **编码**：央视网有的页面声明 UTF-8 实际是 GBK，`net.decode()` 先严格 UTF-8，失败回退 GB18030。

## 已知限制

* **下载下来是 `.ts`**：HLS 分片原样拼接，Kodi / VLC / PotPlayer 都能直接播；
  想转 mp4 需要自己过一遍 ffmpeg（Kodi 里没有 ffmpeg 可执行文件）。
* **最高画质取决于央视公开流**：4K专区 1080P、新闻联播 720P，但今日说法、动画大放映
  这类老栏目的明文流只有 360P。浏览器里能看到的更高画质走的是加密梯（DRM），
  插件不解 DRM，所以只能给到公开流的上限。
* **比赛视频最高 640x360**：赛事里的集锦与回顾是央视按 360P 生产的，逐档解码验过
  （见「赛事」一节）；加密梯里那个 1080P 解出来是乱码，不用。
* **赛事只有近三周**：赛程接口是滚动窗口（今天往前约 7 天、往后 13 天），没有历史
  赛季；世界杯、欧冠这两个热门联赛在当前窗口里一场比赛都没有。
* **2160p 拿不到**：连 CCTV-4K 的明文梯也只是 1080p。
* **下载是单线程顺序拉**：实测约 2.9 MB/s；一部 45 分钟 1080P 约 1.3 GB，按网速换算。
* **栏目单期有限**：栏目页静态只给约 17 期，`index_2.shtml` 已 404；
  约 2/3 的栏目页现在是空壳，这时会自动用栏目名去搜索接口兜底（实测 CCTV-1 覆盖率 98%）。
* **直播可用频道与网络出口有关**：同一个版本，有的网络只能拿到 CCTV-1 / CCTV-13。
* **视频库暂无分类**：`vplist` 的 `cid` 筛选参数含义未确认，目前只给「最新」。
* **体育/财经/军事/纪录片** 没有独立入口：各自子站结构不同，HTML 里内容很少。

**v0.4.2** —— 「能列出清晰度，一选下载就报错」

拿 `kodi.log` 一看就实锤了，两行日志：

```
[cctv] save 720P · 720x1280 · 0.9 Mbps · 00:20 -> …\downloads\…ts
[cctv] download failed: TypeError('function takes at most 2 arguments (3 given)')
```

* **根因**：`_save_stream()` 里写的是 `progress.update(percent, 行1, 行2)`。
  Kodi 21 的 Python 绑定（SWIG）只接受 2 个参数，第三个一传就抛
  `TypeError('function takes at most 2 arguments (3 given)')`。这行代码在**每一片
  分片**上都会执行，所以下完第一片整个下载就中止 —— 前一秒进度框还开着，下一秒
  就报错。清晰度列表不碰进度框，所以「列得出来、下不了」。
  修法：新增 `kodi.progress_update()`，只用 `(percent, 一行文字)` 两参数形式，
  字节数并进同一行；进度框出任何错都只记日志，绝不中断下载。
* **同一份日志里的第二个坑**：`failed to parse old setting definition for "home_limit"
  of type "integer"` + `EXCEPTION: Invalid setting type` —— 整份设置定义都没被接受，
  于是 `getSettingString()` 抛异常、设置界面空白、下载目录改不了。
  根因是 `settings.xml` 用旧版格式（`<settings>` 不带 version），类型名却写成了新版
  的 `integer` / `string`；旧版里整数叫 `number`、文本叫 `text`、目录叫 `folder`，
  只有 `bool` 碰巧两种格式同名才活下来。已全部改回旧版类型名，并把「下载目录」
  换成目录选择框。
* 顺手修掉：下载目录选择框点「取消」会连弹三次（`pick_folder` 把「取消返回空」
  当成了「这个 type 不能用」，现在只对 `TypeError` 换签名重试）。
* 设置里的「首页抓取条数」其实一直没被代码用过，改成「每个板块最多显示条数」并真的生效。
* 回归测试补了 8 项：设置定义必须是旧版类型名、进度框只能两参数（假 Kodi 的
  `DialogProgress.update(percent, message)` 故意只收两个参数），整个下载链路
  仍是真实拉流落盘。

**v0.4.1** —— 1080P 乱码的根因
* 0.4.0 的「1080P」用的是 `hls_enc_url`（`/asp/enc/`），那是**加密梯**：
  TS 结构完好、SPS 能读，但画面数据是加密的，解码满屏 `concealing/corrupt`，
  在 Kodi 里就是花屏。ffmpeg 逐帧验证：加密档解出的 PNG 只有 5~8 KB（空白），
  明文档是 600 KB~1.2 MB 的真画面。
* 改成只走明文 `/asp/hls/` 梯，自己按档位号拼地址（绕开 `maxbr` 裁档位），
  用 H.264 SPS 验出真实分辨率，并按「分片字节数与低档相同」剔除 CDN 的假档位。
* 结果：4K专区真 1080P，新闻联播 720P，抽 28 个样本 0 失败、0 花屏。
